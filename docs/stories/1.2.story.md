# Story 1.2: Admin Authentication

## Goal
Implement secure admin authentication to restrict access to the admin interface, using Supabase Auth (or chosen provider) for login and session management.

## Why
- Protects sensitive admin functionality from unauthorized access.
- Enables role-based access control for future admin features.
- Aligns with security and compliance requirements for the MVP.

## What
- Implement an admin login page.
- Integrate Supabase Auth for email/password authentication (optionally support social login).
- Protect all /admin routes so only authenticated users can access them.
- Store and manage authentication state securely (client and server).
- Provide logout functionality.
- Display error messages for failed logins and handle edge cases (e.g., expired sessions).

### Success Criteria
- [x] Admin login page is accessible at /admin/login.
- [x] Only authenticated users can access /admin and all subroutes.
- [x] Supabase Auth integration is complete and tested.
- [x] Logout button works and clears session.
- [x] Error and edge cases are handled gracefully.
- [x] All authentication logic is covered by tests (unit and E2E).

**Status:** Implemented and validated. Admin authentication is live.

## Anti-Patterns to Avoid
- ❌ Don't store tokens or sensitive data in localStorage (use httpOnly cookies or secure storage)
- ❌ Don't expose Supabase service keys in client code
- ❌ Don't skip tests for authentication logic
- ❌ Don't allow unauthenticated access to admin routes
- ❌ Don't ignore error handling for auth flows
