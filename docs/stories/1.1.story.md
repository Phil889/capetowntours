# Story 1.1: Project & Technical Foundation

## Goal
Set up the initial project structure and technical foundation for the Cape Town Safari Broker application, including a Next.js web app, organized UI components, database integration, and testing infrastructure.

## Why
- Establishes a scalable, maintainable base for all future development.
- Enables rapid feature delivery and consistent developer experience.
- Integrates with all core architectural and business requirements for the MVP.

## What
- Set up a Next.js web application.
- Organize UI components with Tailwind CSS and shadcn/ui.
- Integrate Supabase and Drizzle ORM for database access.
- Set up Playwright for E2E testing.
- Configure ESLint, Prettier, and Vitest for code quality and unit testing.

### Success Criteria
- [x] Web app runs locally and displays a placeholder page.
- [x] UI components (with Tailwind CSS and shadcn/ui) are used in the app.
- [x] Supabase and Drizzle ORM are connected and can run a test query.
- [x] Playwright E2E test runs and passes.
- [x] Linting, formatting, and unit tests pass with no errors.

**Status:** All technical foundation tasks are complete and validated.  
**Next step:** Proceed to Story 1.2: Admin Authentication (implement login, protect admin routes, integrate with Supabase Auth or chosen provider).

## Known Gotchas & Anti-Patterns
```python
# Turborepo: All workspace packages must be listed in pnpm-workspace.yaml
# Next.js: Use App Router for new features, avoid legacy Pages Router
# Tailwind: Ensure PostCSS config is shared across apps/packages
# shadcn/ui: Use the same Tailwind config and CSS variables as the web app
# Supabase: Store credentials in .env, never commit secrets
# Drizzle ORM: Use generated schema, do not hand-write types
# Playwright: Place tests in the e2e package, not in the web app
# Vitest: Use the same tsconfig as the app for type consistency
# Anti-pattern: Do not hardcode config values; use environment variables
```

## Anti-Patterns to Avoid
- ❌ Don't create new patterns when existing ones work
- ❌ Don't skip validation because "it should work"
- ❌ Don't ignore failing tests - fix them
- ❌ Don't use sync functions in async context
- ❌ Don't hardcode values that should be config
- ❌ Don't catch all exceptions - be specific
