# Story 1.3: Create Tour (Backend)

## Goal
Implement the backend logic and API endpoints to allow admins to create new tours, including all required fields and validation, in the database.

## Why
- Enables the admin team to add and manage tour offerings.
- Provides a foundation for the admin UI and public tour catalogue.
- Ensures data integrity and validation at the API/database level.

## What
- Design and implement the database schema for tours (e.g., title, description, price, images, category, duration, availability, etc.).
- Create API endpoints for creating (and optionally updating/deleting) tours.
- Implement input validation and error handling.
- Ensure only authenticated admin users can create tours.
- Write integration tests for the API.

### Success Criteria
- [x] Database schema for tours is created and migrated.
- [x] API endpoint (e.g., POST /api/admin/tours) allows creation of new tours.
- [x] Input validation and error handling are implemented.
- [x] Only authenticated admins can access the endpoint.
- [x] Integration tests cover main scenarios and edge cases.

## Implementation Blueprint

### Data models and structure
```typescript
// Example: Drizzle ORM schema for tours
import { pgTable, uuid, varchar, text, numeric, integer, timestamp } from "drizzle-orm/pg-core"
export const tours = pgTable("tours", {
  id: uuid("id").primaryKey().defaultRandom(),
  title: varchar("title", { length: 255 }).notNull(),
  description: text("description").notNull(),
  price: numeric("price", { precision: 10, scale: 2 }).notNull(),
  category: varchar("category", { length: 100 }),
  duration_days: integer("duration_days"),
  image_url: varchar("image_url", { length: 255 }),
  created_at: timestamp("created_at").defaultNow(),
  updated_at: timestamp("updated_at").defaultNow(),
})
```
