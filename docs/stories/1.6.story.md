# Story 1.6: Admin UI – Manage Tour Availability

## Goal
Enable admin users to manage tour availability by setting the number of available slots per tour per date via an intuitive admin interface.

## Why
- Allows staff to control and update tour capacity in real time.
- Prevents overbooking and ensures accurate availability for users.
- Supports operational flexibility for seasonal or ad-hoc changes.

## What
- Design and implement an "Availability" management UI in the admin dashboard.
- Allow admins to select a tour and view/edit its availability by date.
- Provide controls to set the number of available slots for each date.
- Integrate with the backend to persist availability data (e.g., via a new "tour_availability" table).
- Display success and error messages to the user.
- Restrict access to authenticated admin users only.
- Add loading and error states for API calls.

### Success Criteria
- [ ] Admins can access the "Manage Availability" UI from the dashboard.
- [ ] Admins can view and edit available slots per tour per date.
- [ ] Changes are saved to the backend and reflected in the UI.
- [ ] Only authenticated admins can access the feature.
- [ ] User receives clear feedback on success or failure.
- [ ] UI matches design guidelines and is responsive.

### Per task pseudocode
```tsx
// Task 2: Save handler
const saveAvailability = async () => {
  setLoading(true)
  const res = await fetch(`/api/admin/tours/${tourId}/availability`, {
    method: "POST",
    body: JSON.stringify({ date, available_slots }),
    headers: { "Content-Type": "application/json" }
  })
  if (res.ok) {
    showToast("Availability updated")
  } else {
    showToast("Failed to update availability", "error")
  }
  setLoading(false)
}
```
