# Story 1.11: Admin UI – System Audit Log

## Goal
Enable admin users to view a system audit log of key actions and changes through the admin dashboard.

## Why
- Provides traceability and accountability for critical actions (e.g., user role changes, bookings, logins).
- Supports security, compliance, and operational oversight.
- Helps with troubleshooting and incident response.

## What
- Add an "Audit Log" UI to the admin dashboard.
- Display a list/table of audit log entries with details (timestamp, user, action, target, status).
- Allow filtering/searching by user, action type, and date range.
- Integrate with the backend to fetch audit log data.
- Restrict access to authenticated admin users only.
- Add loading and error states for API calls.

### Success Criteria
- [ ] Admins can access the "Audit Log" UI from the dashboard.
- [ ] Admins can view and filter audit log entries.
- [ ] Audit log entries include timestamp, user, action, target, and status.
- [ ] Only authenticated admins can access the feature.
- [ ] User receives clear feedback on success or failure.
- [ ] UI matches design guidelines and is responsive.

**Status:** Story drafted and ready for implementation.

// Task 2: Fetch audit log handler
const fetchAuditLog = async (filters) => {
  setLoading(true)
  const res = await fetch(`/api/admin/audit-log?${new URLSearchParams(filters)}`)
  if (res.ok) {
    const data = await res.json()
    setAuditLog(data.entries)
  } else {
    showToast("Failed to fetch audit log", "error")
  }
  setLoading(false)
}
