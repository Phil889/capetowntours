# Story 1.10: Admin UI – User Roles & Permissions

## Goal
Enable admin users to view, assign, and manage user roles and permissions through the admin dashboard.

## Why
- Provides granular control over user access and capabilities.
- Supports security and operational requirements for different user types (e.g., admin, staff, viewer).
- Enables scalable and secure team management.

## What
- Add a "Roles & Permissions" management UI to the admin dashboard.
- Display a list/table of all users with their current roles.
- Allow admins to assign or change roles for users (e.g., admin, staff, viewer).
- Integrate with the backend to update user roles.
- Restrict access to authenticated admin users only.
- Add loading and error states for API calls.

### Success Criteria
- [ ] Admins can access the "Roles & Permissions" UI from the dashboard.
- [ ] Admins can view and change user roles.
- [ ] Changes are saved to the backend and reflected in the UI.
- [ ] Only authenticated admins can access the feature.
- [ ] User receives clear feedback on success or failure.
- [ ] UI matches design guidelines and is responsive.

### Per task pseudocode
```tsx
// Task 2: Change user role handler
const changeUserRole = async (userId, newRole) => {
  setLoading(true)
  const res = await fetch(`/api/admin/users/${userId}/role`, {
    method: "POST",
    body: JSON.stringify({ role: newRole }),
    headers: { "Content-Type": "application/json" }
  })
  if (res.ok) {
    showToast("User role updated")
  } else {
    showToast("Failed to update user role", "error")
  }
  setLoading(false)
}
```
